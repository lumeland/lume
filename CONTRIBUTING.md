# Contributing Guide

## How to contribute

This is a collaborative effort. We welcome all contributions submitted as pull
requests.

(Contributions on wording & style are also welcome.)

## Local setup

This is a monorepo managed with [PNPM](https://pnpm.io/).

- The `packages` folder contains all Lume packages.
- The `scripts` folder has some scripts and utilities to help in the automatization of some tasks (maintenance, build, publish, etc).

## Bugs

A bug is a demonstrable problem that is caused by the code in the repository.
Good bug reports are extremely helpful – thank you!

Please try to be as detailed as possible in your report. Include specific
information about the environment – version of Lume, Node, Operating System,
etc, and steps required to reproduce the issue.

## Pull Requests

Good pull requests – patches, improvements, new features – are a fantastic help.
Before create a pull request, please follow these instructions:

- One pull request per feature. If you want to do more than one thing, send
  multiple pull request.
- Write tests.
- Run `pnpm fmt` to fix the code format before commit.
- Document any change in the `CHANGELOG.md` file of the package.

## AI code

Avoid the use of genAI tools to produce code. And if you really need to use
that, please specify which parts are generated by AI in your pull request.

## Testing

Run `pnpm test` to run all tests. If you only want to run the tests of a single
package, run `pnpm --filter [pkg-name] test`. For example `pnpm --filter @lumeland/plugin-base-path test`. The `@lumeland` prefix can be ommited, so `pnpm --filter plugin-base-path test` also works.

To update the snapshots, add the `-u` flag at the end: `pnpm --filter plugin-base-path test -u`.

Run `npmm lint` to run the linter and fix automatically the errors.
